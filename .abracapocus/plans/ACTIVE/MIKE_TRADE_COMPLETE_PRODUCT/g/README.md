# g

## Goal

Implement centralized market and optional research data acquisition. One MarketDataService owns one authenticated Alpaca real-time stock connection for the union of watched symbols/channels and fans normalized immutable events to every live/paper/shadow strategy consumer. Each symbol/channel is subscribed once, never once per strategy or scenario. Default free feed is Alpaca Basic IEX and every event/context/evaluation must retain feed provenance because IEX is not consolidated SIP and IEX volume/VWAP may differ from full-market values. Implement historical-bar access for warmup/backtests and a bounded REST polling fallback that fetches once per symbol/cycle and respects rate limits. Track provider source timestamp separately from receive timestamp, freshness/latency, duplicate sequence/event handling, gaps, entitlement/feed identity, reconnect/backoff, and bounded gap recovery. On feed loss or stale/gapped data, mark DEGRADED and fail new entries closed while broker fills/order updates continue on their separate higher-priority channel. Do not silently merge differently entitled feeds or mix adjusted/unadjusted data without provenance. Shared cache stores latest quotes/trades, compact decision evidence, candle-builder inputs, completed candles, indicator rolling state, and freshness metadata without becoming a raw session tick archive. Strategies are prohibited from direct network polling. Provide a separate ResearchDataProvider port carrying source/publication/observed/ingestion/revision/freshness/missing/licensing metadata; only strategy-declared required research inputs are fetched, mandatory missing inputs produce no signal, and no paid provider/manual upload is required for basic operation. Materialize exactly the five distinct task_hints for this phase; do not merge hints or create extra implementation tasks. Each generated task must have a nonempty implementation description, exact concrete allowed_write_paths drawn only from expected_changed_files, task-specific measurable acceptance_criteria, focused verification_commands, explicit dependencies matching async_notes, and a reasonable task_timeout_seconds. Use allowed_symbols, forbidden_changes, and a bounded decision budget where they reduce ambiguity. Verification-only work must create a real test or audit artifact. Use targeted verification only during this phase; no broad full-suite runs, large backtests, live orders, or paid data acquisition as incidental checks. This PLAN_SKELETON.json is the complete materialization contract for the phase: do not require, request, or consult any external requirements document to understand scope.
