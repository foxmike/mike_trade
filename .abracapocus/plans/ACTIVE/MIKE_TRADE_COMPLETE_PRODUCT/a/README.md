# a

## Goal

Create the production repository foundation for the standalone mike_trade application. Use Python 3.12+ with a reproducible locked environment, a proper package, focused lint/type/test tooling, structured JSON logging, typed application exceptions, architecture/ADR documentation, and a dependency-injected composition root. The architecture is a modular single-engine trading process plus a separate dashboard process; no Kafka, Celery, Kubernetes, generic rules engine, or throwaway script architecture. Freeze module boundaries so domain/strategy/policy code is broker-neutral; adapters live behind ports; app.py/runtime.py compose broker, market-data, research, persistence, clock, scheduler, portfolio, risk, execution, reporting, and controls. Importing modules, reading status, or running tests must never place a live order. README/Make baseline must identify the project as a complete product, point to operator commands, and make live execution explicitly gated. Repository changes are confined to mike_trade and must not touch EventEdge or other projects. The package layout must support domain, strategies, market_data, research, scheduling, signals, portfolio, risk, execution, brokers/alpaca, brokers/shadow, persistence, backtest, reporting, controls, dashboard, observability, tests, config, docs, deploy/systemd, and gitignored state. No secrets are committed. Materialize exactly the five distinct task_hints for this phase; do not merge hints or create extra implementation tasks. Each generated task must have a nonempty implementation description, exact concrete allowed_write_paths drawn only from expected_changed_files, task-specific measurable acceptance_criteria, focused verification_commands, explicit dependencies matching async_notes, and a reasonable task_timeout_seconds. Use allowed_symbols, forbidden_changes, and a bounded decision budget where they reduce ambiguity. Verification-only work must create a real test or audit artifact. Use targeted verification only during this phase; no broad full-suite runs, large backtests, live orders, or paid data acquisition as incidental checks. This PLAN_SKELETON.json is the complete materialization contract for the phase: do not require, request, or consult any external requirements document to understand scope.
