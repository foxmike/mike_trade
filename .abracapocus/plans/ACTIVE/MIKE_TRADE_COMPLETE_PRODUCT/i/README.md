# i

## Goal

Build one engine-owned scheduler for roughly 1-10 watched symbols and every enabled strategy. Support declarative triggers for market-data arrival, quote change, completed 1m/5m/15m/etc candle, explicit interval, session open, entry cutoff, session close, and manual evaluation. A global control cadence is an upper tick, not permission to recompute closed-bar rules on unchanged data. Use asyncio for streams/provider I/O/scheduler, a bounded ThreadPoolExecutor for lightweight independent strategy evaluation, and optionally process workers only for genuinely CPU-heavy future models. Do not create a thread/process per stock or per strategy. Use bounded queues, immutable snapshot versions, watermark/backpressure/coalescing, stale-result cancellation/discard, and deterministic tie-breaking. Never discard fills, broker updates, reconciliation, stop, or safety events. Strategy exceptions are isolated and become explicit ERROR/no-trade outcomes; worker failure can never become BUY. Results enter one ordered decision router, while portfolio/account mutations remain serialized. Revalidate signal expiry and data freshness before order authorization. Implement engine heartbeat, RUNNING/PAUSED/DEGRADED/RECONCILING/OFFLINE-relevant health data, graceful drain that blocks new entries while flushing durable state, and shutdown that does not liquidate or cancel valid protective broker orders. Include an integration proof that ten symbols and multiple strategies share one market-data service rather than opening duplicate provider streams. Materialize exactly the five distinct task_hints for this phase; do not merge hints or create extra implementation tasks. Each generated task must have a nonempty implementation description, exact concrete allowed_write_paths drawn only from expected_changed_files, task-specific measurable acceptance_criteria, focused verification_commands, explicit dependencies matching async_notes, and a reasonable task_timeout_seconds. Use allowed_symbols, forbidden_changes, and a bounded decision budget where they reduce ambiguity. Verification-only work must create a real test or audit artifact. Use targeted verification only during this phase; no broad full-suite runs, large backtests, live orders, or paid data acquisition as incidental checks. This PLAN_SKELETON.json is the complete materialization contract for the phase: do not require, request, or consult any external requirements document to understand scope.
