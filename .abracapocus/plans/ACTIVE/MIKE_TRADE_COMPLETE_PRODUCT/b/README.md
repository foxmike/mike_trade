# b

## Goal

Define precise immutable domain contracts shared by strategies, risk, execution, providers, persistence, shadow, paper/live, and backtests. Use Decimal for USD, prices, quantities, fees, fills, budgets, and sizing; reject NaN/invalid/negative values and leave tick/share precision provider-specific. Store event time in timezone-aware UTC and carry exchange/session identity for New York scheduling. Model Instrument; MarketEvent with provider/feed/source and receive timestamps; Candle with timeframe/OHLCV/closed flag/provenance; immutable MarketContext with freshness/session/optional research; StrategyDefinition and StrategyInstance; Evaluation statuses NO_SIGNAL, SIGNAL, INSUFFICIENT_DATA, STALE_DATA, ERROR, NOT_DUE; Signal with stable ID, ENTER_LONG/EXIT_LONG and extensibility for dormant short/cover without enabling shorts; SignalDecision ACCEPT/REJECT/IGNORE/DEFER; PositionCycle; Position; OrderIntent; BrokerOrder; Fill; AccountSnapshot; BudgetPolicy; ProtectionPolicy; TrailingStopState; TradingSessionPolicy; EntryEligibilityPolicy/State; ControlCommand; and HealthSnapshot. Keep Signal separate from accepted decision, order intent, broker order, fill, position cycle, and broker truth. Symbol is never an account: cash and buying power live at account/scenario level while symbol commitment/P&L are views. External broker positions are unmanaged until explicitly handled. Define broker and market-data provider Protocols, account/capability snapshots, and deterministic serialization/roundtrip support without any Alpaca SDK types in domain modules. Materialize exactly the five distinct task_hints for this phase; do not merge hints or create extra implementation tasks. Each generated task must have a nonempty implementation description, exact concrete allowed_write_paths drawn only from expected_changed_files, task-specific measurable acceptance_criteria, focused verification_commands, explicit dependencies matching async_notes, and a reasonable task_timeout_seconds. Use allowed_symbols, forbidden_changes, and a bounded decision budget where they reduce ambiguity. Verification-only work must create a real test or audit artifact. Use targeted verification only during this phase; no broad full-suite runs, large backtests, live orders, or paid data acquisition as incidental checks. This PLAN_SKELETON.json is the complete materialization contract for the phase: do not require, request, or consult any external requirements document to understand scope.
