# r

## Goal

Implement a real production dashboard as a separate read-only service: FastAPI exposes typed read APIs over read projections and serves a compiled React  + TypeScript frontend built with Vite. React/Vite is a required product choice for this plan; do not replace it with server-rendered-only HTML, HTMX-only pages, a static mock, notebook, or development-only Vite server. The deployed dashboard service must serve production-built frontend assets and remain independently reachable when the trading engine is stopped or crashed. The UI is restrained and operational rather than a professional charting terminal, but it is complete and interactive for monitoring. Global header/banner shows selected account/scenario and mode LIVE/PAPER/SHADOW, engine RUNNING/PAUSED/DEGRADED/OFFLINE/RECONCILING, heartbeat age, broker/data connectivity and freshness, market OPEN/CLOSED/HALTED, exchange clock, next entry cutoff, and stale watermark. OFFLINE is calculated by the dashboard from missed heartbeat and does not depend on the dead engine sending an offline flag. Account KPI area shows cash, buying power, current equity, configured total budget, reserved pending buys, deployed capital, open positions, pending orders, daily realized/unrealized P&L, lifetime/cumulative P&L, unresolved protection/data/reconciliation errors, and provenance/as-of. Account/scenario selector must never merge shadow balances with paper/live or leak state across scenarios. Required watchlist for up to 10 symbols shows symbol+mode, latest price/bid/ask and data age/stale flag, composite trading phase, currently active BUY or SELL strategies, next due trigger/last evaluation, last signal and accepted/rejected reason, confirmed quantity/cost basis/purchase time, per-symbol budget/commitment/planned loss, daily entry count/cap, loss streak/lockout/reset mode, cooldown/next eligible time, minimum-hold remaining, entry cutoff, protection mode/status/price/quantity, native broker HWM or stepped anchor/desired-vs-confirmed stop, last protection update, and realized/unrealized/lifetime symbol P&L. Symbol detail view includes recent evaluation/signal timeline including NO_SIGNAL summaries, trade-relevant evidence/feed provenance, current broker/order tree, protective-order/trailing history with proposed vs confirmed changes, last 20 managed cycles, realized P&L, holding duration, execution slippage and policy decision reasons. Account detail includes broker truth, external/unmanaged holdings, cash/equity provenance, orders, fees/corporate activity/reconciliation. Health view exposes feed age/reconnects/subscription count, broker status/rate errors, scheduler lag, persistence/backup state, reconciliation timestamp, and actionable errors. No dashboard control places orders or changes configuration; display the relevant CLI/Make command text instead. Behavior tests must prove: engine killed -> dashboard stays reachable and becomes OFFLINE within threshold with stale last-known values; feed dead but engine alive -> DEGRADED/no-new-entry indication; broker disconnected -> positions not shown as fresh; partial fill plus protective order -> exact remaining quantity/coverage; trailing display differentiates native broker hwm from stepped local anchor and desired vs confirmed stop; symbol budget/cutoff/lockout/cooldown reasons visible; mode/scenario switching never mixes balances. Bind safely to loopback/LAN by configuration, with remote exposure only behind appropriate private auth/TLS/VPN/reverse proxy. Materialize exactly the five distinct task_hints for this phase; do not merge hints or create extra implementation tasks. Each generated task must have a nonempty implementation description, exact concrete allowed_write_paths drawn only from expected_changed_files, task-specific measurable acceptance_criteria, focused verification_commands, explicit dependencies matching async_notes, and a reasonable task_timeout_seconds. Use allowed_symbols, forbidden_changes, and a bounded decision budget where they reduce ambiguity. Verification-only work must create a real test or audit artifact. Use targeted verification only during this phase; no broad full-suite runs, large backtests, live orders, or paid data acquisition as incidental checks. This PLAN_SKELETON.json is the complete materialization contract for the phase: do not require, request, or consult any external requirements document to understand scope.
