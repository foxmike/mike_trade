## Goal

Integrate, harden, document, deploy, and verify the complete mike_trade product. Provide Ubuntu/R730 engine and independent dashboard systemd units, secure environment/credential setup, state directories/permissions, startup locking, migration/integrity checks, graceful shutdown/drain, backup/restore guidance, operator setup/runbook, architecture/risk/test/dashboard/broker documentation, release checklist, and safe service management. Tests and materialization never perform live orders. Startup must acquire an instance lock; open/migrate/check the correct mode database; load durable controls/config fingerprint; validate credentials, provider capabilities, clock/calendar and asset eligibility; retrieve broker account, open/linked orders, positions and recent activities; match broker facts to local intents/fills exactly once; detect external/unmanaged positions and orphan stops; resolve ambiguous cancel/fill/replacement state; verify budget reservations, entry eligibility, strategy state, and protective coverage; warm required market data; establish feed/order-update freshness; then allow RUNNING/new entries only when reconciled and authorized. Shutdown blocks new entries, flushes state, unsubscribes cleanly, and leaves valid broker protective stops/positions untouched unless a separate explicit close command was issued. Final offline/product acceptance must cover: 1 and 10 symbol shared-feed fanout; independent configurable BUY/SELL rules and parameters; exactly one entry per cycle under repeated signals/partial fills; full remaining discretionary exit after minimum hold; daily entry-cycle count semantics and restart/session reset; symbol and buy-strategy loss lockouts; persistent post-sale cooldown; concurrent budget race; required stop coverage and no oversell; native/stepped trailing initialization, monotonic/multi-step behavior and replace/close races; protection on partial fills; scenario/live isolation; deterministic shadow restart accounting; dashboard OFFLINE/stale behavior; restart with outstanding orders/stops/external trade; early-close-aware cutoff and default no EOD liquidation; stop/pause/close/flatten distinction; exact ledger/report reconciliation for whole/fractional fills; deterministic no-lookahead replay; complete documented Make/CLI surface; and clean reproducible repository/deployment artifacts. The vwap_reference end-to-end proof is mandatory and credentials-free: real production evaluator -> completed-bar VWAP BUY -> one shadow entry -> simulated protective order -> VWAP SELL path with coordinated stop cancellation OR separate stop-first path -> full close -> exact cash/P&L -> cooldown/rearm -> WATCHING_BUY, including duplicate-bar suppression and restart-safe state. It must exercise production components, not a special demo runner. Credential-gated Alpaca PAPER acceptance, once the operator supplies paper credentials and approves bounded test orders, must validate a real paper buy/protection/sell lifecycle, trade_updates/order reconciliation, fractional/order precision and supported fixed/native/stepped protective combinations. Unsupported or unverified combinations remain visibly blocked. Paper fills do not prove live performance. No live order is part of final automated verification. Completion is not allowed with stubs, mock-only Alpaca integration, static dashboard examples, fake provider capability claims, hardcoded BUY strategies, missing migrations/locks, untested restart/reconciliation, missing operational commands, or missing audit/report paths. Use targeted tests throughout and one deliberate final comprehensive acceptance pass only when appropriate; do not start broad backtests/downloads/background jobs as routine verification.
