# k

## Goal

Implement independently selectable SELL plugins and deterministic signal arbitration/rearm. Ship vwap_breakdown, momentum_reversal, and rsi_reversal as real Python modules with validated parameters, declared inputs, methodology/source metadata, closed-bar/reset semantics where applicable, and full-position EXIT_LONG recommendations only. A SELL signal never directly submits an order and never opens a short. For an owned managed position, any enabled valid discretionary sell rule may request closure of 100% of the confirmed remaining quantity. Default policy is first valid exit after prerequisites/minimum hold; simultaneous signals are resolved deterministically and fully audited. Minimum hold blocks ordinary strategy exits only; protective stops, manual close, hard risk exits, and configured forced liquidation bypass it. Stop/manual/risk exit priority is higher than strategy SELL. When flat, SELL rules do not imply opposite-side trading. The required vwap_breakdown reference SELL is exact: completed one-minute regular-session bars with warmed/fresh session VWAP; prior close >= prior VWAP AND latest completed close < latest VWAP. Re-evaluating the same bar cannot duplicate a signal. Build stable rearm state across restart and log rejected/conflicting decisions. The vwap_reference preset must pair independently registered vwap_bounce BUY and vwap_breakdown SELL only by configuration. Ship config/reference_vwap_shadow.yaml as a genuine runnable SHADOW-only configuration using the shared IEX feed, editable symbol, initial shadow funds, budgets, mandatory trailing protection, and 1m completed-candle triggers; it must be structurally incapable of authorizing live orders. Materialize exactly the five distinct task_hints for this phase; do not merge hints or create extra implementation tasks. Each generated task must have a nonempty implementation description, exact concrete allowed_write_paths drawn only from expected_changed_files, task-specific measurable acceptance_criteria, focused verification_commands, explicit dependencies matching async_notes, and a reasonable task_timeout_seconds. Use allowed_symbols, forbidden_changes, and a bounded decision budget where they reduce ambiguity. Verification-only work must create a real test or audit artifact. Use targeted verification only during this phase; no broad full-suite runs, large backtests, live orders, or paid data acquisition as incidental checks. This PLAN_SKELETON.json is the complete materialization contract for the phase: do not require, request, or consult any external requirements document to understand scope.
