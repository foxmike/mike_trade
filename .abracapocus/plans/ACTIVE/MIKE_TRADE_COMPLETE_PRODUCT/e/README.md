# e

## Goal

Build the replaceable Alpaca equity Broker adapter against the individual Alpaca Trading API, not the enterprise Broker API. Paper and live endpoints, credentials, fingerprints, account IDs, state directories, and ledgers are separate with no automatic crossover. Implement bounded authenticated HTTP, structured provider error mapping, retries/backoff for safe reads, rate-limit handling, and no blind retry of order creation. Support read operations for account status, cash/equity/buying power, assets/tradable/fractionable metadata and precision, positions, open orders, lookup by broker order ID and client_order_id, activities/fills/fees/corporate activity where available, and broker clock/capabilities. Support normalized trade_updates streaming for accepted, partial fill, fill, rejection, cancel, replace, and reconnection. Support stock BUY/SELL market/limit orders and protective stop operations only where documented and capability-validated. Preserve quantity-vs-notional choice before submission; enforce known notional replacement restrictions. Native trailing is a standalone trailing_stop sell using trail_price or trail_percent with broker hwm/stop_price/status; it is not an OTO/bracket/OCO leg. Stop-only OTO, bracket/OCO, fractional stop/linked-order combinations, trailing-stop fractional support, stop-price replacement behavior, and DAY/GTC/TIF combinations must be represented in a BrokerCapabilities matrix and remain unavailable/fail-closed when not proven. OTO replacement must not be assumed. Stable client_order_id derives from mode/account + cycle + purpose + attempt and is persisted before send. On network timeout/unknown submission outcome, query by client_order_id before any retry; never send a new ID until original status is resolved. No task or test may submit to live without explicit operator live authorization. Real paper integration remains credential-gated. Materialize exactly the five distinct task_hints for this phase; do not merge hints or create extra implementation tasks. Each generated task must have a nonempty implementation description, exact concrete allowed_write_paths drawn only from expected_changed_files, task-specific measurable acceptance_criteria, focused verification_commands, explicit dependencies matching async_notes, and a reasonable task_timeout_seconds. Use allowed_symbols, forbidden_changes, and a bounded decision budget where they reduce ambiguity. Verification-only work must create a real test or audit artifact. Use targeted verification only during this phase; no broad full-suite runs, large backtests, live orders, or paid data acquisition as incidental checks. This PLAN_SKELETON.json is the complete materialization contract for the phase: do not require, request, or consult any external requirements document to understand scope.
