# q

## Goal

Create the production deterministic historical replay/backtest subsystem, not a disposable script. Reuse the real strategy registry/classes, session calendar, trigger semantics, budget/eligibility policies, position coordinator, protection math, and simulated execution concepts under an injected historical MarketDataProvider and simulated Clock; never call real broker APIs during replay. Replay strictly chronologically with explicit data source/feed/revision/vintage, completed-candle semantics, point-in-time availability, deterministic seed, no future-adjusted or revised data leakage, and explicit quote/bid-ask fidelity limitations. Include halts/early closes/gaps/missing bars/splits/session boundaries. Historical stop simulation must not infer a favorable intrabar order from candle high/low when ordering is ambiguous; model or flag ambiguity/replacement latency. Each bounded operator-selected run writes an immutable manifest with config hash, symbols/window, code revision, data provenance/revision, starting capital, fees/slippage/fill assumptions, seed, and strategy versions plus durable trade/evaluation results. Reports include total/net return, cash/equity, per-trade P&L, drawdown, profit factor, win rate, average win/loss, expectancy net costs, hold duration, entry/exit pairing, favorable/adverse excursion, symbol/month/time-of-day, utilization, sample size and uncertainty, while keeping research/dev separate from untouched holdout and forbidding retuning on locked holdout. No implicit broad history download. Provide bounded synthetic offline fixtures for the vwap_reference pair using production strategy classes: completed-bar upward cross -> one entry -> protection -> downward SELL or stop-first path -> complete close -> exact ledger -> WATCHING_BUY, repeated same-bar/no-signal suppression, and deterministic rerun identity. These tests use no network/credentials and prove no lookahead and no duplicate buy. Materialize exactly the five distinct task_hints for this phase; do not merge hints or create extra implementation tasks. Each generated task must have a nonempty implementation description, exact concrete allowed_write_paths drawn only from expected_changed_files, task-specific measurable acceptance_criteria, focused verification_commands, explicit dependencies matching async_notes, and a reasonable task_timeout_seconds. Use allowed_symbols, forbidden_changes, and a bounded decision budget where they reduce ambiguity. Verification-only work must create a real test or audit artifact. Use targeted verification only during this phase; no broad full-suite runs, large backtests, live orders, or paid data acquisition as incidental checks. This PLAN_SKELETON.json is the complete materialization contract for the phase: do not require, request, or consult any external requirements document to understand scope.
