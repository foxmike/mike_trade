# m

## Goal

Implement the complete restart-safe managed long position cycle for each account/scenario + symbol. Composite lifecycle must cover DISABLED, WATCHING_BUY, ENTRY_RESERVED, BUY_SUBMITTING, BUY_PENDING, PARTIALLY_OWNED, PROTECTIVE_PENDING, WATCHING_SELL, SELL_SUBMITTING, SELL_PENDING, CLOSING, RECONCILING, PAUSED, ERROR, UNMANAGED, and transient CLOSED, while keeping service/order/protection state orthogonal where clearer. One accepted buy signal creates one logical entry cycle; recurring buy signals are ignored until flat and rearmed. First positive partial fill records actual quantity, consumes one daily entry slot, prohibits a second entry, and immediately requires protection reconciliation. Full or partially canceled entry retains actual shares and transitions to sell/protection management rather than automatically buying the missing quantity. Once any real quantity is held, only SELL strategies plus independent risk/protection handlers apply. A valid discretionary exit after minimum hold closes the full remaining managed quantity; partial exit fills update remaining quantity/protection and no new buy is possible until confirmed flat. Final close verifies zero position and no stale sell/protective order before releasing budget and starting cooldown/rearm. Startup/restart obtains broker truth before enabling entries: account, current positions, open/linked orders, recent activities/fills, pending local intents/cancels/replacements, protection coverage, budget reservations, and strategy state. Missing fills are applied exactly once. Unknown broker orders/state or missing stop coverage keeps the symbol RECONCILING/DEGRADED and blocks entries. External positions are shown as UNMANAGED and not automatically attributed/adopted. External/manual closing of a managed position is detected and audited as external/manual exit, not a strategy win. Operator pause blocks new entries while fills, sell/stop/reconciliation continue. Auto end-of-day liquidation exists as optional policy but is disabled by default; operator normally closes manually. Materialize exactly the five distinct task_hints for this phase; do not merge hints or create extra implementation tasks. Each generated task must have a nonempty implementation description, exact concrete allowed_write_paths drawn only from expected_changed_files, task-specific measurable acceptance_criteria, focused verification_commands, explicit dependencies matching async_notes, and a reasonable task_timeout_seconds. Use allowed_symbols, forbidden_changes, and a bounded decision budget where they reduce ambiguity. Verification-only work must create a real test or audit artifact. Use targeted verification only during this phase; no broad full-suite runs, large backtests, live orders, or paid data acquisition as incidental checks. This PLAN_SKELETON.json is the complete materialization contract for the phase: do not require, request, or consult any external requirements document to understand scope.
