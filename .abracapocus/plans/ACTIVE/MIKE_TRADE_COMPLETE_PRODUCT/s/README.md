## Goal

Complete reporting, observability, and the full provider-neutral operator CLI/Makefile contract. Reporting must distinguish account cash from symbol commitment, buying power from authorized project budget, realized from unrealized P&L, gross from net P&L, confirmed fees from estimated/unavailable costs, and trading P&L from deposits/transfers/external flows. Reconcile starting cash + external flows + realized/unrealized P&L to ending equity under explicit valuation/rounding conventions. Implement reports/filtering by account/scenario, day/week/lifetime, symbol, originating BUY strategy, SELL strategy, strategy pair, order/fill, signal/evaluation outcome, rejection reason, holding duration, execution latency/slippage, trailing-stop updates, entry-cap/loss-lockout/cooldown decisions, reconciliation/drift, fees, and live-vs-shadow comparison. Export stable CSV/JSON. Import actual broker activity/fees automatically where available; missing per-order fees remain unavailable/estimated rather than fabricated or manually hand-loaded. Structured logs/metrics include run_id/cycle_id/signal_id/intent_id/client_order_id, market feed age/rates, scheduler lag/evaluation duration, signal/rejection counts, broker REST/WS errors/rates, unknown order states, position drift, shadow fills, P&L, heartbeat, stop placement failures, orphan/expired stops, unconfirmed stepped replacement, stale trailing watermark, uncovered fills, live position with engine offline, unexpected short, risk breach, stale feed, and unhandled exception. Never log secrets/full account identifiers/raw unfiltered provider payloads. CLI and Make targets must include install/update/doctor; config-show; providers/provider-check/broker-check/data-check; strategies/strategy-info/strategy-check; symbols add/remove/enable/disable; strategy enable/disable/set; start/stop/restart/status; dashboard start/stop/dashboard/health; shadow start/stop/list/create/reset; paper start/stop/status; live-preflight/live-enable/live-start/live-disable; pause/resume/pause-symbol/resume-symbol; entries-disable/entries-enable; close/close-all/flatten; trail-status/history/policy-show/policy-set/reconcile; entry-limits/reset/cooldown-status; stop-status/stops-audit; positions/orders/balance/budget/reconcile; signals/evaluations/events/logs; report/report-daily/report-symbol/report-strategy/report-pairs/report-shadow/report-comparison/report-export; backtest/status/report/list; cache-status/refresh; db-check/backup/restore-dry-run; bounded test/lint/typecheck tiers; service install/uninstall/status; help. Make targets call python -m mike_trade.cli/services and contain no duplicated business logic. stop is not flatten; pause keeps protection/reconciliation running; live-mutating commands require explicit CONFIRM_LIVE=YES or equivalent confirmation and cannot silently queue trades while offline. Materialize exactly the five distinct task_hints for this phase; do not merge hints or create extra implementation tasks. Each generated task must have a nonempty implementation description, exact concrete allowed_write_paths drawn only from expected_changed_files, task-specific measurable acceptance_criteria, focused verification_commands, explicit dependencies matching async_notes, and a reasonable task_timeout_seconds. Use allowed_symbols, forbidden_changes, and a bounded decision budget where they reduce ambiguity. Verification-only work must create a real test or audit artifact. Use targeted verification only during this phase; no broad full-suite runs, large backtests, live orders, or paid data acquisition as incidental checks. This PLAN_SKELETON.json is the complete materialization contract for the phase: do not require, request, or consult any external requirements document to understand scope.
